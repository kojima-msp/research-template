# 論文の執筆

読者が一度も推測しなくていい文章を書く。対象・仮定・論理関係・指示語の先行詞・比較の
基準・根拠の出所・主張の範囲を、読者に推測させない。曖昧さが消えるなら、短さより明示を
選ぶ。原稿に無い論理は補わない。足りないものは書き手に返す。

## 進め方

- 文法や表現の修正は edit を出すだけでよい。説明も和訳も添えない。
- コンパイルは、大幅な修正をしたときだけ行う。文法や表現の修正では行わない。
- 文を単独で直さない。段落の役割を決めてから、その中の文を直す。
- 文献を足さない。bib へのエントリ追加も `\cite` の挿入もしない。出典を調べるのは可で、
  書誌情報・その文献が実際に示している内容・反例になりうる記述を示して書き手に返す。
  入れるかどうかは書き手が決める。

## 参照

- 用語・言い回し・節の構成は、`~/paper/` にある添削済みの tex に合わせる (`ja/` 和文、
  `en/` 英文)。該当する表現が無い場合にだけ新しく書く。
- `en/gold/` は構成と言い回しの基準にする。`en/silver/` は用語だけを見る。言い回しと
  主張の強さは真似しない。
- 過去論文は言い回しの証拠であって、写す対象ではない。古い言い回しや残った誤りを
  引き継がない。
- 英文の節ごとの型・動詞・用語の詳細は `house-style.md` を読む。

## 段落

- 1 段落 1 機能。読者の 1 つの問いに答える。同じ話題というだけで別の主張をまとめない。
- 各文の役割 (文脈 / 主張 / 定義 / 仮定 / 機構 / 結果 / 比較 / 限定 / 接続) を決める。
  どれにもならない文は、削るか別の段落に移す。
- 接続語は実際に論理関係があるときだけ使う。however / therefore で論理の飛びを埋めない。
- 近くに置く: 主張と条件、比較と基準・指標、結果と設定、定理と仮定、引用と対象の文、
  記号と定義、指示語と先行詞。
- 段落の途中で対象・データ・仮定の範囲を広げない。
- 段落の分割・統合・順序変更は構造の変更として扱う。文を変えていなくても、主張と根拠、
  結果と条件、定義と記号を引き離さない。

## 用語

- 造語を作らない。分野の標準用語を使うか、数式で定義する。
- 定義していない語を本文で使わない。
- 略語は一度だけ導入し、以後は統一する。
- 繰り返しを避けるためだけに用語を変えない。

## 数式

- まず式を示し、その後に各文字を説明する。
- 式が一行なら `equation` を使う。式の前に改行を入れない。

## 英文の細部

- 動詞を使い分ける。consider (設定)、assume (仮定)、formulate (定式化)、derive (導出)、
  show (直接の根拠を示す)、prove (形式的証明)、indicate / suggest (限定的な示唆)。
- propose は実際の貢献にだけ使う。構成要素ごとに繰り返さない。
- 実験は prove しない。show / indicate / suggest までにする。
- outperform は、指標・比較対象・条件が本文にあるときだけ使う。
- robust は頑健性の実験があるときだけ。significantly は根拠があるときだけ。
- novel / state-of-the-art / for the first time / always を書かない。
- `the proposed method` を繰り返さない。手法名を定義して使う。

## 和文の細部

- 段落頭の「また」などの接続詞を使わない。
- 節をまたぐ「上記の」「前節で述べたように」を使わない。
- 和文中のコロンを使わない。

## 削るもの

- 内部的な言い訳を散文で書かない。式で書けば十分。
- 手法の章で説明済みの内容の再説明。
- 長すぎる一文。主張の補助になっていない説明。

## 主張

- 考察で自分の結果を弱めて終わらせない。事実を歪めない範囲で主張が成立する形に整理する。
- 根拠が支える強さで止める。実験の範囲 (データ・比較対象・指標・条件) を超えて
  一般化しない。

## 図表

- `out/img/` からコピーして `paper/` に置く。元を直接参照しない。
- どの commit の結果を使ったかを `paper/RESULTS.md` に記録する。
- 図表のキャプションに主張・比較・数値・条件を書いたら、本文と同じ基準で確認する。
